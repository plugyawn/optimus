# Quickstart

## Install

```bash
python -m pip install -e .              # library and CPU-side reporting
python -m pip install -e ".[serving]"   # vLLM, for GPU search
python -m pip install -e ".[eval]"      # LightEval, for confirmation
python -m pip install -e ".[dev]"       # pytest
```

GPU runs need a CUDA build of PyTorch and access to the model weights. The
default model is `Qwen/Qwen3-4B`. LoRA materialization is validated for Qwen2,
dense Qwen3 text and Qwen3-VL text configs.

## Data

```bash
optimus make-countdown-data \
  --out data/countdown_generated_1200_seed20260507.json \
  --count 1200 \
  --seed 20260507
```

## Search

Every search names a backend and a method.

| backend | method | use it for |
| --- | --- | --- |
| `transformers` | `dense`, `lora` | trusted reference scores |
| `vllm` | `lora` | the multi-LoRA baseline |
| `vllm` | `subspace` | the batched subspace search described in [how it works](how-it-works.md) |

Trusted dense reference:

```bash
optimus search --backend transformers --method dense \
  --out results/p1024_dense_reference \
  --data data/countdown_generated_1200_seed20260507.json \
  --model Qwen/Qwen3-4B --population 1024 \
  --prompts 64 --holdout-prompts 256 \
  --targets q_proj,v_proj --sigma 0.0075 \
  --max-new-tokens 32 --stop-at-answer
```

Subspace search through vLLM, with the fastest measured kernel settings:

```bash
OPTIMUS_LAZY_DELTA_BACKEND=triton-counter-inplace \
OPTIMUS_LAZY_QKV_KERNEL_POLICY=packed-qkv \
optimus search --backend vllm --method subspace --kernel custom-op \
  --out results/subspace_p128 \
  --data data/countdown_generated_1200_seed20260507.json \
  --model Qwen/Qwen3-4B --population 128 --prompts 8 --holdout-prompts 8 \
  --basis-rank 64 --target-preset qv \
  --scale-mode relative-output-rms --rho-grid 0.01 \
  --max-new-tokens 32 --stop-at-answer
```

`--kernel custom-op` runs the vLLM forward-hook path. Without it, the route
runs the torch reference evaluator. Both refuse to run with prefix caching
enabled.

## Check before you trust a fast backend

```bash
optimus backend-parity-gate \
  --trusted results/backend_parity_gate/peft \
  --candidate results/backend_parity_gate/vllm \
  --out results/backend_parity_gate/gate
```

A fast backend becomes the selector of record only after its rankings and
outputs match the trusted backend. See [evaluation](evaluation.md).

## Confirm with LightEval

Materialize the selected candidates, then evaluate them with a standard
harness:

```bash
optimus materialize-selected \
  --root results/optimus_gpu_suite \
  --out-root results/materialized \
  --mode merged

optimus lighteval-sweep \
  --backend vllm \
  --tasks ifeval \
  --model-template results/materialized/p{population} \
  --populations 128,256,512,1024,4096 \
  --data-parallel-size 8 \
  --max-model-length 4096 \
  --out-root results/lighteval/population_sweep \
  --plan-out results/lighteval/population_sweep/plan.json

optimus lighteval-report \
  --root results/lighteval \
  --out results/lighteval/report
```

## Reports

```bash
optimus systems-report --root results --out results/report/optimus_systems
optimus validate-run --root results/optimus_gpu_suite \
  --systems-out results/report/optimus_systems
optimus release-check --gpu-root results/optimus_gpu_suite \
  --systems-out results/report/optimus_systems --strict
```

The full P1024/P4096 workload is in the [GPU suite runbook](gpu_suite.md).
